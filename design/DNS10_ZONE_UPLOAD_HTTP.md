# DNS10 — source-scoped snapshot upload HTTP boundary

Status: source-only controller contract. No public or live phpIPAM route, upload credential, authentication repository, storage service, worker deployment or production migration is created by this increment.

PR67 requires a separate source-scoped snapshot-upload credential and collector-control credential. The candidate endpoint accepts only `POST` over host-verified HTTPS and `application/json`, with a syntactically distinct `Bearer dnsup1.<32-lower-hex-token-id>.<43-base64url-secret>` credential. A `dnsctl1` control token or browser session cannot authorize upload. The host bridge must bound the raw request stream to 4 MiB plus one byte before allocating an unbounded body; a declared length alone is not sufficient. Responses are JSON, no-store and nosniff; credentials and snapshot contents must never enter responses or diagnostics.

After rejecting oversized or obviously malformed requests, the controller invokes a trusted upload service to authenticate the credential **before** parsing JSON. It then rejects duplicate object keys, including escaped-equivalent spellings, malformed JSON, excess depth or a non-object root. It computes SHA-256 and byte length from the exact accepted raw body and supplies both to the publisher along with the credential and decoded object. The service must reauthenticate and revalidate token revocation, source, dataset selection, collector assignment, job/lease where applicable, all relevant revisions and epoch **inside the same shared-guard transaction** that validates and publishes the complete generation. An authentication result from the initial cheap check is not a lease and must not be reused as authorization after a race.

The publisher must combine the DNS10 snapshot validator, ordering/quota policy and atomic current/previous-generation storage contract. An equal sequence with identical raw digest and size is a no-change replay; conflicts and stale sequences return a bounded conflict response. Current production has none of this receiver, service or source-scoped upload-token lifecycle. The controller's tests use a fake service solely to verify call order and response behavior; passing them is not evidence of token cryptography, database publication or a production endpoint.
