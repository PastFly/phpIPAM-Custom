# DNS10 — selected-zone snapshot storage candidate

Status: source-only schema candidate for an isolated test database. It is not installed and does not collect records. Production DDL requires a separately reviewed migration, exact live-schema checks, backup, available disk assessment and explicit Owner approval; MySQL/MariaDB DDL cannot be assumed transactional. Do not execute this candidate from an HTTP request or apply it to a live database as part of a source test.

PR67 remains the governing design. An explicitly configured dataset belongs to exactly one DNS connection, canonical zone and default instance/scope; the same zone on another connection is a separate dataset. Dataset selection is disabled by default and versioned. No global discovery result automatically creates an active dataset. A generation records the dataset and run identity, source/assignment/dataset revisions, timestamps, byte digest and payload size, with bounded normalized A/AAAA/CNAME/PTR records. A job identifier is retained for audit without a foreign key because normal DNS9 job retention can delete the job independently.

Each dataset's head can reference only generations of that same dataset, with at most one current and one previous pointer. This is enforced by composite foreign keys. Replacing a current generation, moving the old current to previous, pruning the former previous and inserting all records must happen in one shared-guard transaction. Readers see a complete old or new generation. A failure, stale binding, unauthorized source, exhausted budget or incomplete request must leave the old head untouched. Database constraints protect some invariants but do not substitute for authenticated transactions, validator/policy checks, record-count reconciliation or the per-dataset sequence protocol.

All tables are additive and integration-specific. Deleting a connection, collector, dataset or pointed generation is restricted; record rows may cascade only when their owning unreferenced generation is deliberately pruned within a validated transaction. Application code must enforce monotonic sequence and idempotent same-byte replay without refreshing freshness, the 4 MiB uncompressed body and 10,000-record limits, total accounted payload budget, 512 MiB free-space floor, and authorization/revocation checks. The physical storage cost of indexes, redo and undo must be measured separately.

The schema contains no source or collector secret. A future independently authenticated source-scoped upload token, strict JSON receiver, selection UI and runtime worker remain separate missing components. No action here permits DNS writes or native IP/subnet/device mutations.
