# DNS10 — guarded database publication adapter candidate

Status: source-only candidate and isolated MariaDB tests. No token, new job type, schema or PHP file is installed on the live server. Production DDL needs separate Owner approval, actual version/schema compatibility review, backups, disk assessment and a documented recovery plan; DDL is not assumed transactional.

The future adapter implements `IntegrationDnsZonePublicationRepository` using the same phpIPAM `Database_PDO` connection for the full transaction. It establishes phpIPAM's lazy PDO connection before beginning, locks `custom_dns_config_guard` row 1, then reads the upload-token verifier, current source/profile-secret-presence, collector, assignment, selected dataset, job/dataset binding, generations and global payload accounting. It must never retrieve or return the encrypted credential envelope or domain password.

The source-only stacked migration introduces a verifier-only, source/collector/assignment-revision-scoped upload-token table and a `job_id` to selected-dataset/revision binding table. Composite foreign keys reject a binding whose job and dataset belong to different connections. It expands the control-job type constraint to admit `collect_selected_zones`; no existing scheduler or worker creates or executes that type until separately implemented and deployed. The migration does not provision a credential, create a job or select a zone. Source-only DDL must not be run against production as a CI test or browser request.

Compatibility gate: the currently deployed DNS4 poller was written before the new job type and can lease an unknown type. The source branch adds a fail-closed DNS4 guard, but it is not yet deployed. Do not create or schedule any `collect_selected_zones` job after this DDL unless the guarded control path, capable Windows worker and end-to-end version/capability checks have been separately deployed and verified. The source-only guard does not alter the running server.

Generation insert, records, head switch, pruning only the formerly previous generation, completing the exact still-running unexpired job/lease, and a redacted job audit event execute inside one guarded transaction. The adapter fails closed on missing/dangling heads, unexpected row counts, failed writes or ambiguous type conversions. Generation metadata contains job ID but not lease ID or plaintext credentials; job retention remains independent. No SQL in this adapter writes DNS records on Windows or native phpIPAM IP/subnet/device tables.

An exact replay after successful job completion is read-only and retains original timestamps. Token revocation, source or collector disablement, reassignment, selection or revision drift must still deny replay. The adapter must prove rollback and guard behavior against a real disposable MariaDB, including injected failures; a memory fixture alone is not evidence of database atomicity. The future HTTP bridge, administrative token issuance/revocation, job scheduler, worker and selected-zone UI remain outside this increment.
