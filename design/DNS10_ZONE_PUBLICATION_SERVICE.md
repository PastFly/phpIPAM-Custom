# DNS10 — snapshot publication service candidate

Status: source-only application-service contract. No production receiver, credential provisioning, job type, repository adapter, migration apply, worker update or deployment is enabled by this work. PR67 and the DNS10 validation, upload-token, HTTP and storage source contracts remain authoritative.

The initial HTTP authentication runs before JSON parsing. For every publication, a second authentication and full authorization must occur under the same shared DNS configuration guard and database transaction as publication. Resolve the token ID and verifier server-side, require the token active and purpose-separated, source enabled, collector active and still assigned, and the token's stored assignment revision equal to the current assignment. A token is bound to one source and collector; caller-provided IDs or zone names never grant scope.

For a new sequence, resolve the selected dataset and an exact running `collect_selected_zones` job from server-side state. The job must belong to that source, collector and dataset; have one attempt, a delivered credential marker, an unexpired job and lease, and exact current dataset, connection, assignment, binding and credential revisions. The validator compares the submitted sensitive lease ID and other envelope fields with this trusted context. A bare job ID, dataset ID, source token or syntactically valid snapshot does not authorize publication. Any stale, disabled, revoked, unselected or mismatched state fails closed without changing last-good data.

After validation and ordering/resource checks, create the new immutable generation and records, update the dataset head to the new current and old current as previous, remove only the formerly previous generation, and atomically complete the job with the accepted result in the **same** transaction. If any write or audit fails, roll back all changes. No lease ID or token is persisted in the generation or diagnostics. The repository must lock the existing global DNS config guard before these reads and writes, and transactionally protect against concurrent configuration, revocation, selection and job updates.

Immediately before completing the job, re-read the trusted clock and free-space observation. If the lease or job expired during record insertion, clock moved backwards, or remaining free space fell below 512 MiB, roll back the entire transaction; the initial eligibility check alone is not enough for a large snapshot.

Under that guard, the repository must also count every generation for the dataset and resolve both head pointers. A dangling pointer, unreferenced generation, duplicate head, or previous sequence greater than or equal to current is an inconsistent state and must stop publication; it must not be treated as an empty dataset or a sequence reset.

A lost successful HTTP response must allow an exact same-sequence, same-raw-digest, same-length retry without requiring the now-cleared job lease and without changing job, generation, timestamps or record data. This replay is allowed only after current token, source, collector, assignment, selected dataset and all stored generation binding versions still match; the job ID in the identical raw request must be the accepted generation's job ID. The digest covers the entire original body, including its lease and binding fields. Older sequence or equal sequence with different bytes is a conflict. A new sequence always requires a currently active matching lease. The implementation must not trust a submitted digest or byte length outside a trusted HTTP controller that computed them from the raw request.

One completed upload ends the selected-zone job; a future worker must not submit a second successful control-result afterward. A failed collection may use the existing bounded error-result path without publishing records. The currently deployed DNS9 protocol has a 120-second maximum lease and does not support this job type; worker, job binding, lease duration/heartbeat and resource limits require separate design and Windows 5.1/integration verification before use. Do not relax current DNS9 safeguards to force this source contract into production.
