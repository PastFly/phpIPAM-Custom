# DNS10 — selected-zone snapshot validation

Status: source increment only. No receiver, database migration, selected-zone scheduling, production installation or DNS writes are enabled by this increment.

The existing automatic DNS9 worker lists zones. It does not publish their resource records. This increment introduces the pure validation boundary for one complete selected-zone snapshot as a building block for the separate authenticated receiver and atomic last-good storage. The accepted design in PR67 (`cb83531ac5a122b978378e2568a5407b7e551eba`, sections 6–8) remains authoritative: only explicitly selected source/zone/default-scope datasets, A/AAAA/CNAME/PTR class IN, 10,000 records and 4 MiB uncompressed request maximum, no truncation, no native IPAM or DNS writes, and no replacement of last-good data by a failed or partial snapshot.

The future receiver must authenticate with a **separate source-scoped upload credential**, limit raw request bytes and reject duplicate JSON keys before constructing the decoded value; this validator alone does none of those things. The caller must obtain the expected source and dataset identity, normalized zone, configuration revision and binding epoch from authorized server-side state, not the submitted data. The future publication transaction must recheck authorization and all binding versions, enforce positive per-dataset ordering and idempotent replay by exact received-payload digest, account for storage limits, and change the current-generation pointer only after a whole snapshot has validated and persisted. No success in this source increment is evidence of those future controls.

The decoded object is exactly: `schema_version`, `source_id`, `dataset_id`, `zone`, `virtualization_instance`, `zone_scope`, `configuration_revision`, `binding_epoch`, `run_id`, `sequence`, `started_at`, `finished_at`, `supported_types`, `complete`, `record_count`, and `records`. Identifiers are lower-case 32-hex source/dataset IDs; run ID is a canonical lower-case UUIDv4. Sequence is an integer from 1 through 2^53−1. Start/end are positive Unix seconds, ordered, and at most 300 seconds ahead of the receiver clock; older results retain their real collection time. Only default instance and scope are accepted. Empty but explicitly complete record lists are valid; an incomplete snapshot never is.

Each record has exactly `owner`, `display_owner`, `type`, `record_class`, `rdata`, `display_rdata`, `ttl_seconds`, and `source_aging_timestamp`. Normalize DNS owner/target names case-insensitively with terminal dots, support apex, nested, wildcard and underscore labels, require record owners to be within the authorized zone, and never perform DNS resolution. Parse A and AAAA values using the matching address family; CNAME/PTR values are DNS names. TTL is an unsigned 32-bit integer; aging timestamps are null or nonnegative integer seconds and are not freshness indicators. Display fields are bounded text and must be escaped by any future UI. Reject unknown fields, wrong scalar types, invalid names, duplicate normalized owner/type/rdata identities, wrong record counts and out-of-scope data. A root-zone dataset uses `.` as its zone and permits names within the root.

This source increment accepts ASCII DNS labels, including IDNA A-labels, wildcard and underscore labels. Unicode or escaped binary labels are rejected rather than silently changed; future collector integration must explicitly convert or report unsupported names before any pilot, and must never turn a rejection into an empty successful snapshot.

The validator is intentionally storage-agnostic and has no side effects. Passing it is not publication or production readiness. Future code must independently enforce the separate upload credential, raw-body bounds and strict JSON, source authorization, sequence/digest rules, atomic replacement, free-space floor, retention and permissions described by PR67.
